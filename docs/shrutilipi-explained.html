ShrutiLipi

Paste a YouTube URL → get a copyable, downloadable transcript. v1 is captions-only. A pnpm-workspaces + Turborepo monorepo: a Next.js 14 app on Vercel and a FastAPI API on Render, sharing one TypeScript contract package, plus a stdlib-only Python CLI — roughly 2,190 lines of hand-written code across 33 files, with 4 pinned Python dependencies, 3 JS runtime dependencies, and Turbo orchestrating both halves from the root.

The one-sentence version for an interview ShrutiLipi turns a YouTube URL into a plain-text transcript. The interesting part isn't the transcript — it's that the naive way to get captions (asking YouTube directly) fails from cloud hosts, so the backend is built around an environment-configurable provider fallback chain that classifies each failure and reacts differently: fall through, narrow the remaining providers, or stop immediately.

01 Overview

ShrutiLipi (shruti = hearing, lipi = script) is a YouTube transcript extractor. Three entry points, all going through the same backend.

What “v1 = captions-only” actually excludes

There is no audio download and no speech-to-text. If a video has no caption track the API returns 404 no_captions. The frontend copy says so out loud: “No captions found for this video. Try another video (Whisper fallback coming in v2).”

This matters for interviews because it defines the seam for v2: add a WhisperProvider implementing the existing TranscriptProvider ABC, set WHISPER_ENABLED=true, append it to CHAIN_ORDER. Zero frontend changes. The abstraction was designed for the extension before the extension existed.

02 The constraint that shaped everything

Read this section before anything else. Almost every non-obvious decision in the repo traces back to this one fact.

The fact YouTube blocks requests from datacenter IP ranges. On a home connection the obvious implementation works fine: call youtube-transcript-api, get captions, done. On Render's free tier it fails with RequestBlocked from _assert_playability, surfacing as a 502 youtube_blocked.
ConsequenceWhere it lives
Direct caption fetch can't be the only path in productionDIRECT_ENABLED=false in render.yaml:11
Need a hosted provider that transcribes from a different IPSupadataProvider — providers.py:112
Need a last-resort provider too, for when the first is out of quotaSerpApiProvider — providers.py:199
Need to choose between them at runtime without a redeploy per keybuild_provider() — providers.py:346
Need a chain that understands why a provider failedFallbackProvider — providers.py:287
Free Webshare proxies were the first fix; they're dead_get_proxy_config() — youtube.py:63, kept as legacy and documented as “don't debug these”
Since the hosted path works, don't waste 10–20 s on a doomed proxy hop_hosted_levels_active() short-circuit — youtube.py:74
How to say this in an interview “The naive version of this app is thirty lines. It worked on my laptop and failed in production, because YouTube blocks datacenter IPs. That single failure is why the backend has an abstraction layer at all. Once you accept that transcript retrieval can fail in several structurally different ways — the video has no captions, your IP is blocked, your provider is out of quota, the video is age-restricted — you stop writing try/except and start writing a chain that knows which failures are worth retrying elsewhere and which ones are the answer.”

The one-line idea behind handles_missing If a provider just told us this video has no captions, then calling another captions-only provider is guaranteed to fail and will burn quota. Supadata has AI transcription so it is worth trying; SerpApi is captions-only so it gets skipped. The chain narrows itself based on what it learned.

The data model

@dataclass
class TranscriptResult:
    video_id: str
    language: str
    segments: list = field(default_factory=list)
    title: str | None = None

    @property
    def plain_text(self) -> str:
        return " ".join(s["text"] for s in self.segments)

plain_text is a property, not a field. It is recomputed from segments every time, so the text the user copies can never disagree with the segments the user sees. Every provider returns this same shape, which is exactly what makes them interchangeable and the chain possible.

The interface and its policy switch

class TranscriptProvider(ABC):
    handles_missing: bool = True          # <- the policy switch that drives chain narrowing

    @abstractmethod
    def get_transcript(self, video_id: str, lang: str = "en") -> TranscriptResult:
        raise NotImplementedError

The factory

build_provider() is a three-way return, and all three branches matter:

def build_provider() -> TranscriptProvider:
    levels: list[TranscriptProvider] = []
    for name in _parse_chain_order():
        if name == "direct":
            if env_truthy(os.getenv("DIRECT_ENABLED"), True):
                levels.append(CaptionProvider())
        elif name == "supadata":
            key = os.getenv("SUPADATA_API_KEY", "").strip()
            if key and env_truthy(os.getenv("SUPADATA_ENABLED"), True):
                levels.append(SupadataProvider(key))
        elif name == "serpapi":
            key = os.getenv("SERPAPI_API_KEY", "").strip()
            if key and env_truthy(os.getenv("SERPAPI_ENABLED"), False):
                levels.append(SerpApiProvider(key))

    if not levels:
        logger.warning("chain empty (CHAIN_ORDER=%s) -- falling back to direct captions only",
                       ",".join(_parse_chain_order()))
        return CaptionProvider()      # (1) empty  -> bare direct. CORRECT for keyless local dev.
    if len(levels) == 1:
        return levels[0]              # (2) single -> return it unwrapped, no chain overhead
    return FallbackProvider(levels)   # (3) many   -> wrap in the chain
Why branch (2) exists With no API keys — the default local dev state — you get a bare CaptionProvider, not a one-element chain. So local development exercises the real direct path with zero indirection. Returning FallbackProvider([CaptionProvider()]) would be functionally identical but would route every local request through the exception-handling machinery and log a warning per level, making local logs misleading.
_parse_chain_order() — silently drops junk

Config parsing is defensive on purpose. An unknown level name or a duplicate is ignored, not an error, so a typo in a Render env var degrades to “slightly different chain” instead of “service won't boot”.

_CHAIN_DEFAULT = "direct,supadata,serpapi"
_KNOWN_LEVELS = ("direct", "supadata", "serpapi")


def _parse_chain_order() -> list:
    raw = os.getenv("CHAIN_ORDER", _CHAIN_DEFAULT)
    seen, order = set(), []
    for part in raw.split(","):
        name = part.strip().lower()
        if name in _KNOWN_LEVELS and name not in seen:
            seen.add(name)
            order.append(name)
    return order

Interview follow-up: CHAIN_ORDER=serpapi,supadata,serpapi,BOGUS,serpapi parses to ["serpapi", "supadata"]. Order is preserved; duplicates and unknown names vanish. Ask why not raise on unknown — the answer is that a deploy-platform env var is a place where one typo takes down production, and a log warning doesn't.

env_truthy() — why the defaults differ per flag 
def env_truthy(raw: Optional[str], default: bool = True) -> bool:
    """Parse env truthiness: 0/false/no/off -> False; empty/None -> default."""
    if raw is None or not raw.strip():
        return default
    return raw.strip().lower() not in ("0", "false", "no", "off")

Three states, not two: unset falls through to the provider's own default. DIRECT_ENABLED defaults True (you want captions to work out of the box on a home IP); SERPAPI_ENABLED defaults False (it costs money and is emergency-only). That asymmetry lives entirely in which boolean is passed as the second argument at the call site — easy to misread, which is why render.yaml sets DIRECT_ENABLED=false explicitly instead of relying on the default.

Two response-shape defences: a malformed content list is tolerated (non-dict entries are skipped, empty text is dropped), and a completely empty result is promoted to TranscriptsNotFound rather than silently returning an empty transcript. Both matter because “200 OK with garbage” is a real hosted-API failure mode.

SerpApiProvider and the time-unit inference heuristic

SerpApi's docs don't state whether start/duration are seconds or milliseconds. Guessing wrong turns a 3-minute talk into a 300-hour one. So the code inspects the data:

if unit in ("", "auto"):
    # seconds-based caption segments never reach 100s; ms-based rarely drop below 100ms
    unit = "ms" if (max(starts, default=0) > 50000 or max(durations, default=0) > 100) else "seconds"
divisor = 1000.0 if unit in ("ms", "milliseconds") else 1.0

Both signals are needed: a 10-minute video is 600 s, which is under 50 000, so the max(start) test alone would misfire — but its segment durations are around 3 s, which is over 100, so max(duration) catches it. Overridable via SERPAPI_TIME_UNIT=seconds|ms when the heuristic guesses wrong. A per-entry TypeError/ValueError is caught and coerced to 0.0, so one bad row can't kill the batch.

Also in this method: if transcripts is absent it falls back to a plain text/transcript string as a single zero-timestamped segment, and the returned title comes from the same best-effort oEmbed call.

Caption fetching — the two-stage language ladder

fetch_caption_transcript() in youtube.py:102 resolves language in two stages, and the fast path deliberately re-raises:

langs = [lang, "en"] if lang != "en" else ["en"]
# New instance per request: requests.Session is not thread-safe.
api = YouTubeTranscriptApi(proxy_config=_get_proxy_config())

# 1) Fast path
try:
    fetched = api.fetch(video_id, languages=langs)
    return _normalize(fetched.to_raw_data()), fetched.language_code
except Exception as first_exc:
    first_name = type(first_exc).__name__
    # Only fall through for "not found in requested langs".
    # Blocking / unavailable errors should propagate immediately.
    if first_name not in ("NoTranscriptFound", "TranslationLanguageNotAvailable"):
        raise

# 2) Fallback: list() ONCE, then pick the best available
transcript_list = api.list(video_id)
try:    t = transcript_list.find_transcript(langs)                      # exact + en
except: try: t = transcript_list.find_generated_transcript(langs)       # auto-generated
      except:
        try:    t = transcript_list.find_manually_created_transcript(all_codes)  # any manual
        except: t = next(iter(transcript_list))                         # literally anything

Preference order: requested language → English → any manual → any auto-generated → whatever exists. The list() result is reused across all four attempts, so the ladder costs one extra round-trip, not four.

Why the fast path re-raises If the fast fetch fails because the IP is blocked or the video is gone, falling through to list() would issue a second doomed request. The guard restricts fall-through to exactly the two “wrong language” errors, so a block surfaces immediately instead of after a wasted round-trip.

08 The chain algorithm

FallbackProvider.get_transcript() — 36 lines that a linear try/except chain can't express.

def get_transcript(self, video_id: str, lang: str = "en") -> TranscriptResult:
    pending = list(self._levels)
    last_error: Exception | None = None

    while pending:
        level = pending.pop(0)
        name = type(level).__name__
        try:
            result = level.get_transcript(video_id, lang=lang)
            if result.segments:
                logger.info("transcript served by %s video_id=%s segments=%d",
                            name, video_id, len(result.segments))
                return result
            last_error = TranscriptsNotFound(f"{name} returned no segments")
        except Exception as exc:
            last_error = exc

        logger.warning("level %s failed video_id=%s: %s: %s",
                       name, video_id, type(last_error).__name__, last_error)
        if _is_terminal(last_error):        # (1) terminal  -> stop NOW
            raise last_error
        if _looks_missing(last_error):      # (2) missing   -> NARROW the survivors
            pending = [p for p in pending if p.handles_missing]

    if last_error is None:                 # (3) exhaustion -> surface the LAST error
        raise TranscriptError("chain exhausted without an error")
    raise last_error

    11 Error taxonomy

    There are two classification layers, on purpose. Knowing why both exist is the interesting part.

    Layer 1 — typed exceptions carrying a detail

    Everything the new code raises is one of five classes, each carrying the detail string that becomes the API's detail field:

    class TranscriptError(Exception):
    detail = "transcript_fetch_failed"

class TranscriptsNotFound(TranscriptError):   detail = "no_captions"
class ProviderQuotaError(TranscriptError):     detail = "provider_unavailable"
class ProviderAuthError(TranscriptError):      detail = "provider_unavailable"
class ProviderNetworkError(TranscriptError):   detail = "provider_unavailable"

    Quota, auth and network collapse to one detail deliberately: the user cannot act differently on any of them (“retry in a few minutes”), and from outside, distinguishing them would leak which provider is in use and whether your key is still valid.

    Layer 2 — class-name sets plus message sniffing

    Exceptions from the third-party youtube-transcript-api are not wrapped, so they carry no detail. The code classifies them by type(exc).__name__ against three name sets, with substring fallbacks:

    _BLOCK_NAMES   = {"IpBlocked", "RequestBlocked", "FailedToCreateConsentCookie",
                  "PoTokenRequired", "YouTubeRequestFailed", "YouTubeDataUnparsable",
                  "TooManyRequests"}
_MISSING_NAMES = {"TranscriptsDisabled", "NoTranscriptFound", "NotTranslatable",
                  "TranslationLanguageNotAvailable"}
_TERMINAL_NAMES = {"VideoUnavailable", "VideoUnplayable", "AgeRestricted"}
    The genuinely tricky case CouldNotRetrieveTranscript is a catch-all in the library: it wraps IP blocks, consent-cookie failures and genuinely-missing transcripts. It appears in no name set, so both _looks_missing() and _map_error() fall back to reading the message — and the two read it differently on purpose:
    • In providers.py:273–276 the block check runs first: “blocking requests” or (“ip” and “block”) returns False for missing. A wrapped IP block is therefore never mistaken for “no captions”, which would wrongly narrow the chain and return a 404.
    • In main.py:99–108, “could not retrieve” is a missing signal, but lines 106–107 check for the IP-block phrasing first and return 502 youtube_blocked instead of 404 no_captions.
    Both do the specific check before the generic one. Say this out loud in an interview — it demonstrates you've actually met the failure modes rather than pattern-matched a tutorial.

    Why 502 and not 500 for a blocked YouTube ShrutiLipi is up; the upstream it depends on refused. 502 Bad Gateway is the honest code, and it means something specific to monitoring and to retry policies. 500 would claim “we have a bug”, which is both untrue and unactionable. A 404 for “no captions” is equally honest: the resource genuinely doesn't exist.
    _map_error() in full — the exact precedence order 
    def _map_error(exc: Exception) -> HTTPException:
    if isinstance(exc, TranscriptError):                      # (0) typed errors win outright
        return HTTPException(
            status_code=404 if exc.detail == "no_captions" else 502,
            detail=exc.detail,
        )

    name = type(exc).__name__
    msg = str(exc).lower()

    if name in ("InvalidVideoId",) or ("invalid" in msg and "video" in msg):
        return HTTPException(400, detail="invalid_url")
    if name in ("VideoUnavailable", "VideoUnplayable", "AgeRestricted") or "video unavailable" in msg:
        return HTTPException(404, detail="video_unavailable")
    if name in ("TranscriptsDisabled", "NoTranscriptFound", "NotTranslatable",
                "TranslationLanguageNotAvailable") \
       or "no transcript" in msg or "transcripts disabled" in msg or "could not retrieve" in msg:
        # CouldNotRetrieveTranscript wraps many causes; distinguish blocking by message
        if "blocking requests from your ip" in msg or "ip" in msg and "block" in msg:
            return HTTPException(502, detail="youtube_blocked")
        return HTTPException(404, detail="no_captions")
    if name in ("IpBlocked", "RequestBlocked", "FailedToCreateConsentCookie",
                "PoTokenRequired", "YouTubeRequestFailed", "YouTubeDataUnparsable",
                "TooManyRequests") or ("ip" in msg and "block" in msg):
        return HTTPException(502, detail="youtube_blocked")
    return HTTPException(502, detail="transcript_fetch_failed")

    Read it as an ordered list of guards where the first match wins. The typed-error branch is first, so a deliberate ProviderQuotaError can never be reclassified by a lucky substring match. The substring fallbacks such as "invalid" in msg and "video" in msg are a hedge against upstream exception classes being renamed: a rename then degrades to a generic 502 instead of an unhandled 500.

    Classifying a hosted provider's error string

    Hosted APIs return HTTP 200 with an error field in the body, so status-code mapping alone isn't enough. Two helpers handle it:

    def _raise_hosted_error(source: str, msg: str) -> None:
    low = str(msg).lower()
    if any(h in low for h in ("quota", "credit", "exhaust", "rate limit", "too many",
                              "billing", "plan")):
        raise ProviderQuotaError(f"{source}: {msg}")
    if any(h in low for h in ("api key", "api_key", "unauthorized", "forbidden", "invalid key")):
        raise ProviderAuthError(f"{source}: {msg}")
    raise ProviderNetworkError(f"{source}: {msg}")


def _map_hosted_status(resp, source: str) -> None:
    if resp.status_code in (401, 403):  raise ProviderAuthError(f"{source}: auth failed ({resp.status_code})")
    if resp.status_code in (402, 429):  raise ProviderQuotaError(f"{source}: quota/rate limited ({resp.status_code})")
    if resp.status_code == 404:         raise TranscriptsNotFound(f"{source}: transcript not found")
    if resp.status_code >= 500:       raise ProviderNetworkError(f"{source}: upstream {resp.status_code}")

    The keyword lists are informed guesswork about third-party wording, and that's an honest weakness worth naming: if Supadata changes its error text, a quota error silently becomes a network error. Both map to the same HTTP 502 and the same user-facing string, so the blast radius is small — which is exactly why quota, auth and network share a detail. 402 is included because that's how both vendors signal “out of credit”.

    The once-only bootstrap

    Why a ref and not a state flag The effect depends on searchParams, whose object identity can change on re-render. A useState flag would be read as stale within the same effect pass and, worse, setting it would schedule an extra render — the classic “effect runs twice because I set state inside it” bug. A useRef mutation is not a render trigger, so the guard is free. It also survives React.StrictMode's double-invoke in dev, which matters because next.config.js sets reactStrictMode: true — a double fetch would burn provider quota.

    Re-entrancy guard — protecting paid quota

    async function runFetch(urlValue: string, langValue: string) {
  if (!urlValue.trim() || loading) return;      // guard 1: in code
  setLoading(true); setError(null); setData(null);
  try {
    const result = await fetchTranscript(urlValue.trim(), langValue);
    setData(result);
    try {
      const qs = `?url=${encodeURIComponent(result.videoId)}&lang=${encodeURIComponent(langValue)}`;
      window.history.replaceState(null, "", qs);
    } catch {
      // history API unavailable -- shareable link just won't update
    }
  } catch (e) {
    setError(e instanceof Error ? e.message : "Something went wrong.");
  } finally {
    setLoading(false);
  }
}

    Guard 1 is the early return; guard 2 is disabled={loading || !url.trim()} on the button in UrlInput.tsx. Belt and braces against a double spend on a 100-req/month free tier.

    Progressive-enhancement details worth naming
    • Clipboard with a fallback. navigator.clipboard.writeText is unavailable in non-secure contexts, so both TranscriptView.tsx:16 and ShareButtons.tsx:99 fall back to a hidden <textarea> plus document.execCommand("copy").
    • Theme before first paint. layout.tsx:41 injects a raw IIFE into <head> that reads localStorage["shrutilipi-theme"] and adds the dark class before React hydrates, with suppressHydrationWarning on <html> because the server always renders the light-less markup. Without it, dark-mode users get a white flash on every load.
    • Download without a library. Blob + URL.createObjectURL + revokeObjectURL, filename ${videoId}.txt (TranscriptView.tsx:32).
    • Share without SDKs. ShareButtons.tsx hand-builds wa.me/?text=, t.me/share/url, the X intent, the Facebook sharer and mailto: from a single ${origin}/?url=<id>&lang=<lang> string. Every external link gets rel="noopener noreferrer".
    • Defensive browser calls. history.replaceState and localStorage.setItem both sit in try/catch with a comment explaining the graceful degradation, instead of a bare catch {}.
    • cache: "no-store" in fetchTranscript — correctness beats a cached 404.
    formatTime() — implemented twice, once per layer

    packages/shared/src/index.ts:73 (TypeScript, imported by TranscriptView) and tools/fetch.py:42 (Python) implement the same rule: if hours are greater than zero print h:mm:ss, otherwise m:ss. A 5-minute video must not read 0:05:30.

    function formatTime(s: number): string {
  const total = Math.max(0, Math.floor(s));
  const h = Math.floor(total / 3600);
  const m = Math.floor((total % 3600) / 60);
  const sec = total % 60;
  if (h > 0) return `${h}:${String(m).padStart(2, "0")}:${String(sec).padStart(2, "0")}`;
  return `${m}:${String(sec).padStart(2, "0")}`;
}

    Duplication across a network boundary is acceptable — sharing it would require a shared runtime or server-rendered formatting. Flag it as a known trade-off rather than pretending it doesn't exist.

    The two decisions that matter

    1. stdout versus stderr discipline

    The transcript goes to stdout; every statistic, progress line and error goes to stderr (print(msg, file=sys.stderr)). That's what makes python tools/fetch.py ID | pbcopy and > notes.txt produce clean output. rich.Console(stderr=True) is constructed with stderr=True for the same reason. Pure Unix discipline, in a Python script.

    2. Exit codes as an API

    Batch mode and the Windows launcher

    Batch (run_batch, fetch.py:110) is sequential, and each fetch is forced to out="-" so every video writes <videoId>.txt in the current directory. A failure does not abort the run — it records a row and continues. With rich you get a transient Progress bar (Spinner / Text / Bar / MofN / TimeElapsed) and a green-red summary Table; without it, [i/n] <url> lines on stderr plus a batch done: ok/total ok (exit N) footer. Sequential rather than parallel on purpose: it keeps provider quota predictable and output ordering stable.

    Launcher — tools/shrutilipi.bat, annotated in tools/README.md:72:

    %~dp0 is the script's own folder, which makes it cwd-independent and space-safe. %* passes every argument through unchanged, and the explicit exit /b %errorlevel% keeps the exit-code contract intact through the batch layer. Add the folder to PATH once and you can run shrutilipi <id> from anywhere.

    19 Your 2-minute and 10-minute stories

    The 2-minute version — “walk me through this”

    “ShrutiLipi turns a YouTube URL into a plain-text transcript. Three entry points: a Next.js frontend on Vercel, a FastAPI backend on Render, and a stdlib-only Python CLI. One endpoint, GET /api/transcript?url=&lang=, returning the video ID, title, language, plain text and timestamped segments.

    The interesting part is what happened when I deployed it. The obvious implementation — call youtube-transcript-api directly — worked perfectly on my home connection and returned a 502 in production, because YouTube blocks datacenter IP ranges. That is the entire reason the backend has an abstraction layer.

    So I built a provider chain. Three levels — direct captions, Supadata, SerpApi — assembled from environment variables at startup. The key design decision is that a fallback chain usually isn't a linear retry, because the failures aren't equivalent. If a provider says ‘this video has no captions’, calling another captions-only provider is a guaranteed miss that spends quota, so the chain narrows. If a provider is blocked or out of quota, that's about its reach rather than the video's content, so it falls through. And if the video is private or deleted, no provider will ever succeed, so the chain stops immediately and reports the real reason.

    That policy lives as a single class attribute, handles_missing, on each provider. SerpApi is captions-only so it sets it false; Supadata has AI transcription so it sets it true. The chain just filters on it.

    Around that: a 24-hour in-memory cache written only on success, a typed error taxonomy that maps to stable detail codes so the frontend can show specific copy, and shareable URLs where the address bar is rewritten to the canonical video ID so the result itself is the shareable link. I also wrote a CLI that shares the same quota and uses exit codes 0, 1 and 2 for scripting. About 2,190 lines, four Python dependencies, in a pnpm/Turborepo monorepo.
